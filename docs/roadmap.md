# План после первой версии

Первая версия = базовая функциональность, проверенная на живом провайдере (ноут, Manjaro) и
финальный прогон на Fedora. Пункты ниже — после неё.

## Качество выбранной стратегии (согласовано)

Сейчас подбор берёт первую стратегию, пробившую все хосты; критерий — TLS-ответ в пределах
таймаута. Не ловит: замедление видео (ТСПУ пропускает handshake, но режет поток `googlevideo`),
стратегии, тормозящие сами (`wssize`, ретрансмиты), разницу между узлами Google.

1. **Ручная обратная связь.** После подбора: «Откройте видео. Всё нормально?» + кнопка
   «Тормозит — попробовать следующий способ» (продолжить подбор со следующего кандидата).
2. **Пассивный замер скорости видео.** Во время реального просмотра считать байты по
   соединениям к `googlevideo` (счётчики nft / conntrack), показывать «видео ~X Мбит/с»;
   ниже порога (1–2 Мбит/с для 720p) — предлагать следующий способ. Синтетическую закачку
   видео не делаем: URL подписаны, а без правильного `n`-параметра YouTube сам режет скорость.

## Предложено, не решено

- Ранжирование кандидатов вместо «первый прошедший»: прогон всех, выбор по стабильности
  (`REPEATS` 3–5, нужен ~100% успех), затем по медианному времени соединения.
- Нейтральное название приложения в UI вместо «YouTube без блокировок» (товарный знак).
