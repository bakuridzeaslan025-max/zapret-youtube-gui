# Решения

## D1. Движок — только zapret2 (`nfqws2` + `blockcheck2`) — 28.09.2026

**Выбрано:** zapret2 (bol-van/zapret2, MIT). Один движок и в рантайме, и в автоподборе.

**Почему:**
- zapret1 объявлен EOL 12.01.2026 (только багфиксы, новых техник не будет). DPI меняется —
  приложение на замороженном движке устареет.
- `blockcheck2` умеет `TEST=custom` (прогон своего списка стратегий из
  `list_https_tls12/13.txt`) и стандартный перебор с обрезкой (`SCANLEVEL=quick`, `NOTEST_*`,
  `BATCH=1`, `DOMAINS=...`). Этапы 1 и 2 автоподбора — один харнес, один формат summary
  (`<test> ipv4 <domain> : nfqws2 <args>` + блоки `* COMMON` / `* COVERAGE`).
- Статические `nfqws2` под linux-x86_64/arm64 в релизах (~322 КБ, lua встроен), рядом
  `lua/*.lua` и `files/fake/*.bin`.
- Опыт автора (шлюз) — уже на zapret2.

**Цена:** стратегии flowseal написаны под winws (= zapret1 nfqws). Нужен свой транслятор
winws → nfqws2. Готового конвертера нет, есть только раздел «портирование стратегий nfqws1» в
`docs/readme.md` zapret2 и список семантических отличий (badseq, tcp_ts, рандом tls-mod,
ipv6 autottl, multidisorder через reasm). Набор опций flowseal ограничен (~29 уникальных).
Перевод делается ОДИН РАЗ: результат коммитится в `strategies/` и дальше поддерживается
вручную, к flowseal не возвращаемся. Транслятор — одноразовый инструмент, не часть сборки;
неизвестная опция в нём = ошибка, а не молчаливый пропуск.

**Отвергнуто:**
- zapret1 целиком — EOL.
- Два движка (nfqws для flowseal + nfqws2 для перебора) — двойная поддержка, два набора
  nft-правил/сервисов, ради того, что транслятор решает один раз.

**Риски и как смягчаем:**
- Переведённая стратегия ведёт себя иначе, чем winws-оригинал → каждую переведённую стратегию
  проверяем на реальном канале; в JSON храним исходник рядом с переводом.
- `blockcheck2` в худшем случае ~28k проверок (часы) → этап 2 только с жёсткой обрезкой
  (quick, только TLS, IPv4, `MAX_TTL=0` и т.п.), с прогрессом и отменой в GUI.
- nfqws2 зависит от версии lua (`NFQWS2_COMPAT_VER`) → бинарник и lua кладём из одного релиза,
  версию пиним.
- `blockcheck2` при запущенном nfqws2 только предупреждает (`check_already`), но наши nft-правила
  и очередь мешают тестам → на время подбора останавливаем свой сервис.
- nfqws2 делает droproot до чтения lua → lua в `/opt/...` с 0755 по всему пути или `--uid=0:0`.

## D2. Стратегии flowseal — извлечены разово, дальше свои под гитом — 28.09.2026

`strategies/extract_flowseal.py` → `strategies/flowseal.json` (flowseal commit `249a704`, MIT).
22 YouTube-профиля → 18 после дедупликации. Нужен один fake: `tls_clienthello_www_google_com.bin`.
Во flowseal YouTube десинкается только на 443. Особый случай — ALT5 (без hostlist, `syndata` →
в очередь нужно слать и исходящий SYN). `FAKE TLS AUTO` использует `midsld` — может не пробить
`youtubei.googleapis.com` (см. CLAUDE.md).

## D3. GUI — Electron — 28.09.2026

**Выбрано:** Electron (решение автора). Макет из Claude design — HTML, переносится как есть.
Упаковка — electron-builder → AppImage (x86_64, arm64).

**Архитектура:** Electron (main + renderer) работает от пользователя. Всё привилегированное
(установка в `/opt`, nft, systemd, blockcheck2) — через `pkexec` отдельного helper-скрипта,
скопированного в `/opt` при установке (root не читает FUSE-маунт AppImage). Renderer к системе
доступа не имеет: только через preload/IPC с узким API.

**Цена/грабли:** AppImage ~100+ МБ. Ubuntu 23.10+/24.04 ограничивает unprivileged user namespaces
через AppArmor → песочница Chromium в AppImage может не стартовать (известная проблема
Electron-AppImage). Решать осознанно (AppArmor-профиль при установке через pkexec — мы и так
ставим компоненты с root), не глушить `--no-sandbox` по умолчанию.

## D4. Root-режим (nfqws2) без userspace-альтернативы — 28.09.2026

Рассмотрены: (1) nfqws2 с root — установка в `/opt`, systemd, nft, polkit; (2) tpws как
локальный SOCKS без root — ничего не ставится, но слабее (без fake-пакетов), только
proxy-aware приложения, свой подбор, tpws — из EOL zapret1; (3) гибрид 2→1.

**Выбрано (1).** AppImage = «один файл скачать», не «ничего не ставить». Экран «нет модуля ядра»
— редкий крайний случай: install.sh сам делает `modprobe` + `/etc/modules-load.d`, ошибку
показываем только если модуля физически нет (урезанные ядра).

## D5. Репозиторий и лицензия — 28.09.2026

GitHub `bakuridzeaslan025-max/zapret-youtube-gui`, public. Лицензия проекта — MIT (совместима с

## D6. Установщик сам ставит недостающие пакеты — 28.09.2026

`install.sh` доустанавливает `nft`/`curl` штатным менеджером (apt/dnf/zypper/pacman) без
отдельного вопроса — пользователь и так подтвердил установку паролем. Модули ядра — `modprobe`;
экран с командой — только если модуля физически нет.
