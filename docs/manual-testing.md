# Ручная проверка на живом провайдере

Прогоняется на реальном железе в двух сетях: **дом** (проводной или Wi-Fi) и **4G** (USB-модем или
раздача с телефона). Фейковый DPI-стенд (`tests/dpi-stand/`) это не заменяет: только здесь видно,
пробивает ли стратегия настоящий ТСПУ. Пути и имена — из `system/lib/common.sh`.

## 0. Подготовка

- [ ] Чистая машина (или после п. 8): `ls /opt/ytunblock` → нет, `nft list tables | grep ytunblock` → пусто.
- [ ] Записать: дистрибутив и версию, ядро (`uname -r`), DE, версию AppImage, провайдера и тип сети.
- [ ] Без приложения YouTube в браузере не работает (иначе проверять нечего — отметить в отчёте).
- [ ] `sysctl net.ipv4.tcp_timestamps` — записать значение (от него зависят `ts`-стратегии).

## 1. Установка

- [ ] Запустить AppImage → «Установить» → один запрос пароля (pkexec), без ошибок.
- [ ] На Ubuntu 24.04+ окно открылось без `--no-sandbox` (AppArmor-профиль встал).
- [ ] Появились: `/opt/ytunblock/`, `systemctl cat ytunblock.service`,
      `/usr/share/polkit-1/actions/org.ytunblock.helper.policy`.
- [ ] Список недостающего (`requirements`) пуст или понятен; при недостающем — внятное сообщение.
- [ ] Повторный запуск AppImage не просит установку заново.
- [ ] Включение/выключение из GUI не спрашивает пароль.

## 2. Проверка сети — все три вердикта

- [ ] **dpi**: сервис выключен, провайдер блокирует → вердикт «DPI», по хостам видно, какие висят.
- [ ] **unblocked**: включить сервис с рабочей стратегией (или сеть без блокировок/VPN) → все 4 хоста ок.
- [ ] **path** (проблема не в блокировке): резать весь HTTPS, тогда и контрольный невинный SNI висит:
      ```sh
      sudo nft add table inet ytutest
      sudo nft 'add chain inet ytutest out { type filter hook output priority 0; }'
      sudo nft add rule inet ytutest out tcp dport 443 drop
      # проверить в GUI → вердикт «path», подбор не предлагается
      sudo nft delete table inet ytutest
      ```
- [ ] Время проверки разумное (при DPI — порядка таймаута ~9–10 с, не минуты).

## 3. Подбор стратегии

- [ ] **Быстрый** (сервис выключен, вердикт dpi): прогресс идёт, ETA правдоподобна, в конце —
      найдена стратегия (id) или честное «не нашлось» с предложением глубокого.
- [ ] Отмена посреди подбора: остановился, сервис вернулся в прежнее состояние,
      `nft list tables | grep blockcheck` → пусто, `pgrep nfqws2` — только сервисный (или ничего).
- [ ] **Глубокий** (если быстрый не нашёл, либо принудительно из расширенного режима): доходит до
      конца, результат применяется; записать длительность.
- [ ] После применения «Проверить» → unblocked по всем 4 хостам.

## 3a. Нужен ли wssize (собственные стратегии)

Решает судьбу `own-wssize-multidisorder` (см. `strategies/README.md`). На том же провайдере по
очереди применить (расширенный режим → выбор способа) и проверить все 4 хоста + видео 1080p:
- [ ] `own-multidisorder-hostmid` (без wssize) — результат: ___
- [ ] `own-wssize-multidisorder` — результат: ___
- [ ] Если без wssize работает так же → wssize не нужен: убрать `own-wssize-multidisorder`
      из `strategies/` (профиль без hostlist не делаем). Если только с wssize → в сервисе нужен
      отдельный профиль без hostlist для SYN (замедлит начало всех HTTPS-соединений) — решение
      за пользователем.

## 4. Реальное видео

- [ ] youtube.com открывается, поиск и превью работают (api + thumbs).
- [ ] Видео 1080p играет ≥ 3 мин без остановок, перемотка в конец и начало работает (video).
- [ ] «Статистика для сисадминов»: буфер растёт, соединение не рвётся.
- [ ] QUIC отрезан: в DevTools → Network → Protocol у `googlevideo.com` — `h2`, не `h3`.
- [ ] Второй браузер (Firefox/Chromium) — то же самое.

## 5. Смена сети

- [ ] Дом → 4G: GUI замечает смену сети; для новой сети стратегии нет → предлагает проверку/подбор.
- [ ] Подобрать на 4G, вернуться домой → применилась домашняя стратегия без подбора (при `perNetwork`).
- [ ] Раздача с телефона по Wi-Fi определяется как Wi-Fi — записать, что показал GUI.

## 6. Перезагрузка и автозапуск

- [ ] Автозапуск вкл → reboot → `systemctl is-active ytunblock.service` = active, видео играет
      без открытия GUI.
- [ ] Автозапуск выкл → reboot → сервис не запущен, таблицы `inet ytunblock` нет.
- [ ] Таймер обновления: `systemctl list-timers | grep ytunblock` — есть, пока приложение установлено.

## 7. Выключение

- [ ] «Выключить» → `systemctl is-active ytunblock.service` = inactive, `nft list table inet ytunblock` —
      нет, `pgrep nfqws2` пусто, YouTube снова блокируется (вердикт dpi), остальной интернет работает.

## 8. Удаление

- [ ] «Удалить» из GUI → запрос пароля (всегда, даже с polkit-правилом).
- [ ] Ничего не осталось:
      ```sh
      nft list tables | grep -e ytunblock -e blockcheck      # пусто
      systemctl list-unit-files | grep ytunblock             # пусто
      pgrep -a nfqws2                                        # пусто
      ls -d /opt/ytunblock /var/lib/ytunblock /var/log/ytunblock /run/ytunblock \
        /usr/share/polkit-1/actions/org.ytunblock.helper.policy \
        /etc/apparmor.d/ytunblock-appimage /etc/modules-load.d/ytunblock.conf   # всё «No such file»
      ```
- [ ] Интернет работает, после reboot ничего не поднимается.
- [ ] Повторная установка после удаления проходит с нуля.
